# 共通ハーネス（KitaKita Lab の全リポジトリ共通の AI 運用ルール）

KitaKita Lab のリポジトリで Claude Code と Codex が同じ判断原則で動くための、共通ルールの**正本**。
このフォルダの `profiles/*.md` を変えると、各リポジトリの `AGENTS.md` にある管理ブロックへ、更新の PR として展開される。

## 仕組み

| 項目 | 内容 |
|---|---|
| 正本 | `harness/profiles/<名前>.md`（このリポジトリの `main`） |
| 各リポジトリでの置き場所 | `AGENTS.md` の管理ブロック（`<!-- BEGIN:kitakita-harness <名前> rev=… -->` 〜 `END`）。固有ルールはブロックの外に書く |
| Codex | `AGENTS.md` をそのまま読む（ブロックの中の「Review guidelines（KitaKita Lab 共通）」も PR レビューの観点になる） |
| Claude Code | `CLAUDE.md` の 1 行目 `@AGENTS.md` で、セッションの開始時に `AGENTS.md` ごと読み込む（URL からの読み込みはできないため、各リポジトリに文面を置く） |
| 版 | ブロックの `rev`（本文の SHA-256 の先頭 12 桁）。正本と同じなら最新 |
| 展開 | `npm run harness:sync -- apply <フォルダ>`（ファイルを書くだけ）→ AI が各リポジトリに Draft PR を作る → 人間がマージ |
| 展開状況 | `npm run harness:sync -- status <フォルダ> ...`（最新 / 古い版 / 手で変更 / 未導入、`CLAUDE.md` の読み込みの有無） |

### プロファイル

| 名前 | 内容 | 入れるリポジトリ |
|---|---|---|
| `common` | 優先順位・仕事の進め方・人間だけが行うこと・状態の記録（GitHub と Notion）・報告・共通のレビュー観点 | すべて |
| `creative` | 視覚的な成果物の制作（比較して決める・人間の承認が正・AI 生成画像の扱い・終え方） | POP・バナー・スライド・Web のビジュアルを作るリポジトリだけ |

どのリポジトリにどれが入っているかは、各リポジトリの `AGENTS.md` の管理ブロックそのものが記録になる（このリポジトリは公開のため、非公開リポジトリの一覧はここに書かない。一覧と展開状況は Notion の「共通ハーネス｜運用方針とプロジェクトの入口」にある）。

## 共通ルールと固有ルールが食い違うとき

`common` の「優先順位」のとおり。

1. 固有ルール（ブロックの外）が優先する。厳しくするのは自由。
2. 「人間だけが行うこと」を緩める固有ルールは、人間の承認と範囲が明記されているときだけ有効。
3. 決められないときは安全側（実行しない・止めて聞く）。
4. 管理ブロックは手で書き換えない。手で変更されたブロックは `apply` が上書きせずに止まる（固有の事情をブロックの外に移してから展開する）。

## 共通ルールを変えるとき（手順は `.claude/skills/harness-sync/SKILL.md`）

1. `profiles/*.md` を変える PR をこのリポジトリに作る（人間がマージ）。
2. マージ後、AI が導入済みのリポジトリを探し、`apply` で管理ブロックを更新して、リポジトリごとに 1 つの Draft PR（ブランチ `claude/harness-sync`）を作るか、開いている同じブランチの PR を更新する。
3. 各リポジトリの検査（CI）と Codex レビューを通し、人間がマージする。

無限更新・PR の乱立を防ぐ決まり：

- `apply` は同じ正本に何度かけても結果が同じ。変更がなければ commit も PR も作らない。
- 1 つのリポジトリに開く同期 PR は 1 つだけ（同じブランチを更新する）。
- 自動の点検は「導入済みで古い版」のリポジトリだけを更新する。未導入のリポジトリへの導入は、人間が依頼したときだけ行う。
- 同期 PR は管理ブロックと `CLAUDE.md` の 1 行以外を変えない。

## できないこと（制約）

- Claude Code・Codex が文面に必ず従うことは保証できない。保証できるのは「セッションの開始時に読み込まれる場所に、同じ文面がある」ことまで。
- 各リポジトリへの反映は PR のマージ（人間）が必要。マージされるまで、そのリポジトリでは古い版のまま動く。
- GitHub Actions だけで他のリポジトリに PR を作るには、人間がトークンか GitHub App を用意する必要があるため、使っていない（展開は AI のセッションが行う）。
