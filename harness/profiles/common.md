# KitaKita Lab 共通の AI 運用ルール

このブロックは KitaKita Lab のすべてのリポジトリで共通（正本は `kitakita-lab/kitakita-lab` の `harness/`）。Claude Code は `CLAUDE.md` の `@AGENTS.md` から、Codex は `AGENTS.md` から、同じ文面を読む。

## 優先順位

1. このブロックの外に書かれたリポジトリ固有のルールが、共通ルールより優先する。固有ルールで厳しくするのは自由。
2. 下の「人間だけが行うこと」を緩める固有ルールは、人間が承認したことと適用範囲がそのリポジトリに明記されているときだけ有効（例：公式サイトの実績追加の自動公開）。
3. どちらとも決められない食い違いは、安全側（実行しない・止めて人間に聞く）をとり、報告する。
4. このブロックは手で書き換えない。共通ルールを変えるときは正本を変える PR を作る（固有の事情はブロックの外に書く）。

## 仕事の進め方

- **目的起点**：着手前に、何を達成する仕事か・成功条件・制約を短く言語化する。依頼と目的が食い違えば、実装前に理由と代替案を示す。
- **既存情報を自分で取る**：人間に聞く前に、リポジトリ（README・AGENTS.md・docs・案件の記録・台帳・コミット履歴）、Issue・PR、Notion の状況ボードと歴史記録（接続できる場合）を確認する。調べて分かることは質問しない。質問は、調べた範囲と不足だけを示して一度にまとめる。
- **重さに応じた事前検討**：新しい制作・設計・仕組みの変更は、既存の成果物や過去の判断との整合・選択肢・失敗のリスクを検討してから着手する。誤字や小さな修正は検討を省いて直す。既存の修正依頼で、不要な再設計をしない。
- **AI が実行する**：調査・設計・実装・検証・修正・成果物の整理・記録・引き継ぎは AI が行う。人間に求めるのは、目的・優先順位・予算・成果物の評価・最終承認だけにする。
- **終了条件**：作業ごとに終了条件を決め、満たしたら止める。品質に実質的な影響のない修正や、必要性を説明できない仕組みの追加はしない。改善案は作業を終えてから出す。

## 人間だけが行うこと（AI は方法や理由を問わず実行しない）

- PR のマージ・`main` への変更・Draft の解除
- 本番への公開・デプロイにつながる操作
- 外部への送信・共有（取引先・印刷会社・SNS・メール・note などへの投稿や入稿）
- 費用が発生する操作（有料プラン・購入・課金の契約）
- ブランド表現・文言・デザインなどの最終判断（AI は推奨まで）
- 保護設定・承認条件・検査の緩和（CI・ゲートの弱体化、許可リストへの追加を含む）
- リポジトリの公開範囲・権限、Notion の共有設定の変更

## 状態の記録（会話の中だけに残さない）

次の AI が前の会話を知らなくても、現在地から再開できるようにする。

- **GitHub が正本**：コード・成果物の台帳・設定・テスト、作業状態（Issue・PR）、判断の詳細、検証の記録。案件の現在地（決定事項・未実施・次の工程）は案件の README などリポジトリ内に書く。
- **Notion は案内板**：「KitaKita Lab｜AI司令塔 状況ボード」に、プロジェクトの現在地・重要な決定とその理由・次の工程・人間の判断待ち・GitHub の参照先だけを書く。GitHub の詳細を複製しない。食い違えば GitHub を正とする。
- Notion の更新は節目（着手・承認待ち・完了）だけ。ボードの「現在の状態」の範囲だけを範囲指定で書き換え（ページ全体の置き換えはしない）、「履歴」に 1 行追記する。区切りの詳細は子ページを 1 件作る（作成後は書き換えない）。新しいデータベースは作らない。プロジェクトごとの現在地の入口は、ボードの子ページ「共通ハーネス｜運用方針とプロジェクトの入口」。
- Notion に接続できない・許可を求められたときは、作業を止めずに「Notion 未反映」と報告する。権限設定は変えない。
- ページの URL・ID、秘密情報、個人情報、取引先の名称、金額は、公開リポジトリにも Notion にも書かない（各リポジトリの情報管理ルールに従う）。

## 報告

- 日本語で、結論から。事実・推測・意見を分け、実際に検証できたことと設計上の想定を分ける。
- 人間に判断してほしいことは、選択肢と推奨を添えて最後にまとめる。

## Review guidelines（KitaKita Lab 共通）

- 「人間だけが行うこと」を AI や自動処理が実行するようになっていないか
- 検査・CI・承認条件が弱められていないか
- 秘密情報・個人情報・取引先の情報が Git や公開物に入っていないか
- 依頼の範囲外の変更や、必要性の説明がない仕組みの追加がないか
