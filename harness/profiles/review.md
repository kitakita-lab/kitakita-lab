# Codex レビューの回数（KitaKita Lab 共通・Codex のレビューを使うリポジトリ）

このブロックは、PR で Codex のレビューを受けるリポジトリに共通の回数のルール（正本は `kitakita-lab/kitakita-lab` の `harness/profiles/review.md`）。上の「KitaKita Lab 共通の AI 運用ルール」の優先順位に従う。

- **上限は義務ではない**。品質の条件（下の「終える条件」）を満たしたら途中で終える。回数を消化するためだけの依頼はしない。
- **区分と上限**（Codex が実際にレビューした commit の数）：軽微 1 回／通常 3 回／基盤（初期実装・ビルド・依存関係）5 回／重要領域 5 回。
  - 重要領域：金額計算、金融データの取り込み、認証・権限、機密情報・個人情報、データの削除・上書き、外部への送信、税務上の確定処理、CI・検査・ゲート・AI の運用ルール。
  - 区分は「変更したファイルから機械的に決まる下限」と「AI の申告」の高い方。判定できないときは低リスクとして扱わない（通常以上）。AI は区分を上げてよいが、下げられない。下げるのは人間だけ。
  - 軽微の 1 回目で修正が必要な指摘が出たら、軽微ではなかったとして通常に上げる。
- **数え方**：依頼の回数と、有効なレビュー（受領のある commit）の数を分けて数える。応答のない依頼はレビュー回数に含めない。同じ commit への再依頼は、回数と間隔を制限する。応答がない・完了しないレビューを合格扱いにしない。
- **依頼の前**：CI と自動テストが成功していること。指摘は採用・却下・保留に分け、採用した指摘はまとめて直してから再レビューを依頼する。指摘の重大度（P0〜P3）だけで終えない。影響と修正の必要性で判断し、修正が必要な指摘が残っていれば終えない。
- **終える条件**：最新の commit を Codex がレビュー済みで、修正が必要な未解決の指摘がない。実質的な修正を入れたら、上限の範囲で再レビューする。
- **同種の指摘の繰り返し**：2 回続いたら、原因の分析と回帰テストを PR に記録してから再レビューを依頼する。3 回続いた、または新しい重大な不具合が続けて見つかる場合は、上限が残っていても止めて人間に報告する。
- **上限に達したら止める**（CAPPED。合格ではない。未解決の指摘が残っていれば FAIL を優先する）。続けるか・マージするかは人間が決める。修正 commit の数の上限は、レビューの上限とは別に管理する。
- **記録**：PR ごとに、レビューの依頼回数・有効なレビューの回数・区分・各回の指摘と採否・止めた理由を、Issue（または PR の台帳）に残す。
- **技術的な強制**：レビューの回数を数えて止めるゲートがあるリポジトリでは、ゲートの判定に従う。ゲートがないリポジトリでは、この節は手順書による運用で、技術的には強制されていない（報告にそう書く）。
- **ルールを変える PR**：レビューの回数や区分を変える PR では、マージ前の新しいルールを自分に当てはめない（上限を広げない）。いま有効なルールで依頼・判定する。
- リポジトリ固有のルール（上の「優先順位」）で上限を低く決めている場合は、そちらに従う。
